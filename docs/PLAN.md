# 自己的下载器：多渠道 + 中文原生界面（替代迅雷）

## Context
- 测试结论（10-27）：公开片源上 Gopeed 全面快于非会员迅雷（起速 5–18s vs 45–64s/不动；海外源 5 MB/s vs 0）。迅雷会员只在命中它服务器缓存时短暂爆发。
- 用户要：一个客户端搞定多渠道（磁力/BT/HTTP/网盘/视频站），浏览器一点就下，中文、有 logo、不 low，最终不用迅雷。
- **真实边界**：「比迅雷会员还快」只在一种情况做不到——迅雷服务器缓存命中的冷门资源。那是它花钱建的缓存网络，开源客户端补不了；唯一同类替代是「云端离线下载」服务（PikPak 等，也是付费会员）。本方案不承诺这一项，其它场景目标是追平或超过。

## 判断：LinkSwift 有没有用
- 有用，但只管「网盘」一个渠道：在网盘网页里拿直链，交给下载器多线程拉。**不破解限速**——百度非 SVIP 直链照样慢；夸克/阿里/123 等限速松的网盘提升明显。
- ⚠️ GitHub 上 `Mario82del/LinkSwift` 让下载「安装程序」，疑似冒名仓库（真项目是油猴脚本，作者 hmjz100，Greasy Fork 发布）。只装 Greasy Fork 版，exe/dmg 一律不碰。
- 百度另有 Gopeed 官方扩展 `gopeed-extension-baiduwp`（同样 SVIP 才满速）。

## 迅雷快在哪 → 我们怎么对应
| 迅雷技术 | 免费可做的对应 |
|---|---|
| 自建缓存 CDN（会员高速通道） | 做不到；可选接云端离线下载服务（以后再议） |
| P2SP 多源混合 | aria2/Gopeed 多镜像 + BT 网页种子 |
| BT 加速 | 自动更新 tracker、开监听端口 + UPnP（被连入才有速度，Gopeed 目前端口随机）、DHT |
| 被墙源 | 走 Clash 代理（迅雷做不到，实测这是最大优势） |
| 防封 | 按站点限连接数（国内镜像 16 线程会 403/418，实测踩过） |

## 架构（推荐）
自己做一个原生 SwiftUI Mac 客户端（中文、自己的 logo），**不重写下载引擎**：
- **引擎 1：Gopeed 内核**（官方 headless 版 `gopeed-web-v1.9.3-macos-arm64`，REST API）→ HTTP/磁力/BT/ed2k
- **引擎 2：yt-dlp + ffmpeg**（本机已装）→ B 站/YouTube/抖音/小红书等视频站
- **网盘**：LinkSwift（浏览器端）拿直链 → 发给客户端
- **浏览器**：Gopeed 浏览器扩展指向我们内置的内核端口，点链接直接进我们客户端
- 为什么不改 Gopeed 的 Flutter 界面：要装 Flutter 工具链、以后跟上游合并痛苦；SwiftUI 跟小清同一套技术，界面能做到原生质感。

## 普通下载排查（10-28 晚，用户：「普通下载为啥都出问题，全部排查一遍」）
测试矩阵（临时内核、正式配置；对照 curl / aria2c）：GitHub 302 签名地址、中文 Content-Disposition、分块无长度、不支持 Range、国内镜像、极小文件、SourceForge 跳转、动态 zip、空文件 —— **内核全部正确**。问题都在下面几处：
- [x] 1. **内核：下载中途服务器回 429/5xx 后任务永远「下载中」不报错**（本地服务器复现：8 MB 卡在 6 MB，/continue 后照旧）；续传时跳过重试满 3 次的连接（fetcher.go Resume）后没人做完成检查。改补丁：连接全挂时报错；429/503 读 Retry-After 退避、减连接
- [x] 2. **确认框解析把整个文件在后台下一遍**：`/resolve` 的 HTTP asyncPrefetch 把文件完整下到 $TMPDIR/gopeed-prefetch-*，App 又用原链接新建任务 → 每个普通下载下两份、请求翻倍、临时文件不清。改：新建任务用解析得到的 rid（内核复用这次连接），或解析只取头
- [x] 3. **确认框解析不带浏览器的 Cookie/Referer/UA，也不走代理**（`resolveForPanel` 丢了 headers）→ 要登录 / 防盗链 / 境外的链接在确认框里解析失败
- [x] 4. **解析失败时文件名被改坏**：普通文件的默认名也套了片名整理（`NewTaskPanel.swift:73` PrettyTitle），存成没后缀的「…Academiënpaleis jpg」。改：只对磁力/种子/视频整理，普通文件保留原文件名
- [x] 5. **小文件也开 8 个连接**：维基 3.8 MB 图片 8 连接 + 自动重试 → 429 + retry-after 600。参照 aria2（单服务器 1 连接、小于 20 MB 不分段）：小文件 1 连接，大文件慢启动
- [x] 6. **接管范围太宽**：浏览器里存一张图片也被接走，App 一失败用户就没了这次下载。改：图片/网页类和已知很小的文件留给浏览器；App 接手后很快失败的退回浏览器重下
- [x] 7. **错误提示**：内核原话「http request fail, code:429」改成人话（服务器限制下载频率 / 链接过期 / 需要登录）
